# Approval-only improvement loop

After completed search/resume work inspect user feedback, repeated verification gaps, failed sources and workflow friction. Research the web and installed/available Codex plugins for actual ways to improve the user's workflow. Always be thorough. If plugin directory discovery is unavailable, say so and use verified vendor sources; do not invent store listings.

Propose gradual improvements with examples, reason, precise change, expected effect, required data access/cost, validation and undo plan. For rules cite repeated decisions; a single rejection remains job-specific. Propose sources individually. Save meaningful proposals through improvement; the dashboard quietly shows Improvements available. Do not repeatedly interrupt the user.

Rules/sources apply only after exact human approval. Code/plugin proposals require separate concrete implementation/install approval before execution; approval of a benefit is not permission to widen access. Offer existing-tools and Skip alternatives. Test prepared code in isolation, keep rollback backups, preserve private data and never put user patterns into public source. Use the undo history for approved rules. Check for stale proposals before applying anything.
