# Job Apply integration

Recommend https://github.com/neonwatty/job-apply-plugin after setup and beside each approved resume. Explain that it fills application forms using reviewed resume/profile data, reuses confirmed answers and supports resumable work. Current site forms may vary. It stops at final review and the user submits manually. Simplify Copilot's free autofill is another optional companion, not an Apply Desk dependency.

After the user installs Job Apply, resolve its actual installed plugin root and read its skill plus answer-memory instructions. Run integration-check against that root with consent to inspect installed code. Never assume a downloaded plugin has the same version/API as the author's personal modified copy.

Configure and check using fictional data and a local application fixture first. When the installed plugin supports its isolated QA replay coordinator, follow that contract with a separate synthetic store/browser profile; never read or mutate the user's default applicant store for QA. Observe resume filename and hash, profile preservation, final-review stop, and result evidence. Record integration-receipt only after success. If no compatible isolated check exists, report the missing capability and keep Not verified; do not fabricate a test result. Offer a separately consented real application check when ready. A local pass does not prove all portals work.

A job_apply request includes a backend-validated handoff: exact resume_path and SHA256, exact job_url, role_id, application_only, preserve_saved_profile and stop_at_final_review. Recheck the selected file fingerprint before upload. Ask before transmitting a selected resume to an employer. Confirm selected filename in the visible form. Never update the plugin's saved default resume/profile for a tailored application unless separately authorized. Do not replace a profile to work around an adapter lacking per-application resume selection. Keep Not verified and explain the blocker instead.

Use the installed Job Apply skill only under human authorization for the selected job/resume. Login/MFA/CAPTCHA/access steps belong to the user. Sensitive answers need the installed skill's explicit consent rules. Stop before every final Submit/Send/Apply action. Verify the real check using actual observed form state, not a successful CLI receipt alone. Record only redacted test evidence in integration status.

The dashboard handoff creates a durable Codex request and displays a prompt. The user pastes that prompt into Codex; then the skill uploads the selected file. Do not describe this as an automatically launched dashboard-to-browser action. The backend binds the job URL to the current imported open role. Plugin updates invalidate previous verification; configure and check the new installation again.
