# Career coach and approved resume workflow

Read only the master and supporting files the user selected. If facts are missing, interview them with grill-me. Invite voice for longer stories. Confirm employer/role context, personal ownership, actions, outcomes and evidence. Never invent facts, dates, achievements, credentials or metrics. Record confirmed facts through `fact` with text, context and confirmed true only after the user confirms the fact. Imported documents supply evidence, not automatic approval of rewritten language.

Register via `master` with docx, optional pdf and consent true. Word on macOS currently establishes the master's real baseline page count. Supporting folder intake uses `inventory` (folder), then `import-files` (selected ids, consent true). Never auto-select an entire folder or newly added files. Preserve snapshots and their fingerprints.

Study the role and propose only bullets whose rewrite materially improves specificity, relevant evidence, clarity or emphasis. All other master bullets carry forward exactly. For each change use `proposal` with role_id, slot_id (from master.bullets), text, reason and confirmed fact_ids. Explain why it is better and how the evidence supports it. The review UI shows only changes, highlighted additions/deletions, reasons and source facts. Missing evidence triggers follow-ups before a proposal; if unavailable use a narrower supported improvement or retain the original.

Human approval covers exact wording and evidence. Do not approve, shorten, merge, replace or paraphrase approved text yourself. Edits need a new pending proposal. Rejecting a proposal retains original master text. Do not substitute bullets from another employer. User presses Generate Word + PDF once after decisions; the backend leaves pending wording out and blocks unresolved proposals. All unchanged bullets carry through.

Preserve fonts, sizes, emphasis, margins, spacing, native bullets/indents, tables/borders, hyperlinks, section order and master maximum page count. Never alter formatting for fit. Overflow requires approved shorter wording or user-approved content selection. Complex mixed-format bullets may need an explicit run mapping; do not silently flatten them. Unsupported renderers remain a setup blocker. Never promise Windows/Linux fidelity without testing a renderer.

Inspect all generated PDF pages against the registered reference, including links, employer tables, bullet alignment and clipping. Only mark visual-review after actual inspection. A rendered page count alone is not visual approval. Use host document/PDF tools and their render/inspection requirements. Preserve the master and save outputs separately in out/resumes. For existing private workspaces the registered master and their standing resume instructions remain the authority.

Only one approved wording version may exist per role/master bullet. To revise an approved version, the user withdraws its approval, reviews the replacement and approves that exact wording. Active/embedded or remote-loading Word content is rejected before native rendering; normal contact hyperlinks remain supported. Never bypass that guard to open a supplied file.
